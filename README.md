# Task Tracker: общая база данных (Supabase) на Netlify

Приложение остаётся на Netlify. Данные хранятся в Supabase (PostgreSQL), вход по почте и паролю, доступ защищён Row Level Security. Всё начинается с чистого листа: ничего переносить не нужно. Проекты, которые вы создадите, будут одинаково отображаться на компьютере и телефоне.

Старые данные в браузере (если они есть) приложение не читает и не трогает. Их можно игнорировать.

## 1. Supabase (один раз, около 10 минут)
1. Зайдите на supabase.com → **New project**. Выберите регион ближе к вам, придумайте пароль базы и сохраните его (в приложение он не вводится).
2. Слева **SQL Editor** → **New query** → вставьте весь файл `supabase/schema.sql` → **Run**. Скрипт создаёт таблицы, правила доступа (RLS), индексы и Realtime. Его безопасно запускать повторно.
3. **Authentication → Users → Add user → Create new user**: введите свою почту и пароль, отметьте **Auto Confirm User**. Это ваш аккаунт для входа.
4. **Authentication → Sign In / Providers**: отключите **Allow new users to sign up**. После этого никто посторонний не сможет создать аккаунт.
5. **Authentication → URL Configuration**: в **Site URL** и **Redirect URLs** укажите адрес вашего сайта на Netlify. Это нужно для письма восстановления пароля.
6. **Project Settings → API**: скопируйте **Project URL** и **anon public key**.

## 2. Netlify
**Вариант А. Перетаскиванием (как вы публикуете сейчас).**
1. Откройте файл `config.js` в блокноте. Замените `https://YOUR-PROJECT.supabase.co` на ваш Project URL, а `YOUR-ANON-PUBLIC-KEY` на anon public key. Сохраните.
2. В Netlify откройте ваш сайт → **Deploys** → перетащите папку со всеми файлами этого архива в область «Drag and drop your site output folder here». Новый сайт создавать не нужно: адрес останется прежним.

**Вариант Б. Из Git или Netlify CLI.** **Site configuration → Environment variables**: добавьте `SUPABASE_URL` и `SUPABASE_ANON_KEY` (значения из шага 6). Файл `netlify.toml` при сборке сам создаст `config.js`.

Что можно публиковать: Project URL и anon public key. Они публичны по замыслу Supabase, а данные защищает RLS.
Чего нельзя вставлять ни в `config.js`, ни в код приложения, ни в переменные для клиента: **service_role key**, пароль базы данных, JWT secret.

## 3. Первый запуск
1. Откройте сайт, введите почту и пароль из шага 3 и нажмите «Войти». Кнопка «Первый запуск» не нужна: аккаунт уже создан в Supabase (при отключённой регистрации она вернёт ошибку).
2. Откроется пустой Dashboard. Создайте проект («+ Проект») или нажмите «Загрузить демо-данные», чтобы попробовать на примере.
3. Откройте сайт на телефоне, войдите той же почтой и паролем: проекты и задачи будут теми же.

Вход сохраняется на устройстве. Выйти можно в «Настройки → Выйти».

## 4. Как проверить синхронизацию
1. Создайте проект на компьютере → откройте сайт на телефоне: проект на месте.
2. Создайте задачу на телефоне → на компьютере она появится через 1–2 секунды без обновления страницы.
3. Отметьте её выполненной на компьютере → на телефоне статус обновится.
4. Добавьте запись дневника на компьютере → откройте дневник проекта на телефоне.
5. Закройте и снова откройте вкладку: данные и вход на месте.
6. Отключите интернет и измените задачу: появится плашка «Нет соединения», изменение сохранится на устройстве. После возврата сети оно отправится само, статус вверху экрана вернётся к «Сохранено».

Статус в шапке: «Загрузка…», «Сохранение…», «Сохранено» (данные подтверждены базой), «Нет соединения» или «Ошибка сохранения» (нажмите на него или на «Повторить»).

## 5. Если что-то не так
- Приложение не просит вход и работает «по-старому»: в `config.js` остались значения `YOUR-…`, либо файл не попал в публикацию. Проверьте и опубликуйте заново.
- «Неверная почта или пароль»: проверьте пользователя в Authentication → Users (должен быть подтверждён).
- «Ошибка сохранения»: убедитесь, что `schema.sql` выполнен без ошибок, а в `config.js` anon key, а не service_role.
- Письмо восстановления пароля ведёт не туда: проверьте Site URL и Redirect URLs (шаг 5).

## 6. Ограничения
- Если одну и ту же запись одновременно изменить на двух устройствах, сохранится последнее изменение. Изменения разных записей не конфликтуют.
- История изменений и вложения подгружаются при открытии проекта.
- Вложения хранятся в самой базе (до ~700 КБ на файл). Для больших файлов позже стоит перейти на Supabase Storage.
- У каждого пользователя пока свои данные. Общий доступ к проектам нескольких людей не реализован, но схема его допускает (все строки привязаны к `owner_id`).
- На бесплатном тарифе Supabase нет автоматических бэкапов: делайте копию в «Настройки → Полная резервная копия (JSON)». Проект на бесплатном тарифе «засыпает» после недели без активности, первый запрос после паузы будет долгим.
